# xv6 进程调度实验平台：立项与实施方案

## 1. 任务开始说明

本仓库是项目的第 0 个里程碑（M0），目标不是马上堆叠功能，而是把所有人固定在同一个、可追溯的 xv6 原始版本上。M0 的完成定义如下：

## 2. 选题

### 题目

**面向教学的 xv6 进程可观测性与多级反馈队列调度实验平台**

### 题目动机

xv6 的进程模型和调度器足够小，适合逐行理解，但原始系统难以回答“一个进程为什么获得 CPU”“它等待了多久”“策略改变后是否真的改善交互任务”等问题。本项目先增加低侵入、可验证的进程计数和观测接口，再实现可开关的 MLFQ，用统一负载比较轮转/默认策略与 MLFQ。

### 明确边界

第一阶段只研究单机、内核内调度和用户态观测，不承诺实时性、公平性证明、持久化日志或网络监控。默认策略必须继续可用；MLFQ 是实验策略，不应破坏 fork、sleep/wakeup、退出回收和多核启动。

### 可交付成果

1. `getpinfo`（名称可在设计评审时调整）等最小观测接口，能安全返回进程快照和调度计数。
2. 可配置的 MLFQ：队列优先级、时间片、老化/提升规则均有常量或明确配置点。
3. 用户态 `ps`/实验程序和自动化测试，覆盖计数正确性、抢占、睡眠唤醒、fork/exit、饥饿避免和多核回归。
4. 一份可复现实验报告，给出基线与 MLFQ 在 CPU 密集、IO 密集和混合负载上的数据，而不是只展示主观现象。

## 4. 路径规划

| 路径 | 当前职责 | 预计变化 |
| --- | --- | --- |
| `kernel/proc.c` | `allocproc`、`fork`、`scheduler`、`sched`、`yield`、`sleep/wakeup`、`exit/wait` | 进程计数、队列元数据、MLFQ 选择与状态迁移 |
| `kernel/proc.h` | `struct proc` 和进程状态 | 增加优先级/队列级别、时间片和计数器；保持锁注释清晰 |
| `kernel/trap.c` | 时钟中断、用户/内核陷阱分流 | 在明确的时钟路径更新运行/抢占计数，避免重复记账 |
| `kernel/sysproc.c`、`kernel/syscall.*` | 进程系统调用与分发 | 增加只读快照接口和可选策略切换接口 |
| `user/user.h`、`user/usys.pl`、`user/` | 用户 ABI、汇编桩、命令和测试 | 增加 `ps`、负载生成器和回归测试 |
| `Makefile` | 内核、文件系统和用户程序构建 | 加入新用户程序及可选实验参数，默认目标不改变 |
| `scripts/` | 主机侧运行/采集辅助脚本 | 统一 QEMU 启动、超时、输出保存和多次实验汇总 |
| `docs/` | 设计、实验和结果记录 | 保存 syscall/锁设计、路线图、数据和已知限制 |

## 5. 逐步修改和实现方案

### M0：基线与环境（当前）

- 锁定上游提交 `9e3161a9abf5f51ea402562d1874caf6c4926597`。
- 确认 RISC-V GCC、QEMU、Python 测试脚本的版本并记录在实验报告。
- 运行一次 `make qemu` 启动检查；运行一次已有 `usertests`/`test-xv6.py`（工具链可用时）。
- 产出：本文件、协作约定、干净基线提交。

### M1：理解路径和测试先行

- 闫保捷绘制 `scheduler -> swtch -> trap -> yield` 的调用链，列出锁获取顺序。
- C 先加入不依赖新 syscall 的 CPU/IO 负载程序和输出格式。
- D 固化一条可重复的 QEMU smoke test，确保新测试能区分“进程运行”和“进程睡眠”。
- 产出：不改变调度行为的测试提交；所有人从同一测试开始开发。

### M2：最小进程观测接口

- 闫保捷先在 `struct proc` 增加运行所需的最小计数器，并在单一时钟/上下文切换边界记账。
- A 设计快照结构和 syscall：只复制稳定字段，明确 `copyout` 失败和并发读取语义；不要把内核指针暴露给用户。
- C 实现 `ps` 和一个能持续 CPU/主动 sleep 的对照程序，加入 `Makefile`。
- D 增加非法地址、进程退出中和进程数上限测试。
- 通过标准：默认调度器行为不变；计数单调、不越界；`fork/exit/wait` 和多核回归通过。

### M3：MLFQ 数据模型和策略开关

- B 写一页设计说明，先确定队列数、优先级方向、每级时间片、老化阈值、提升周期和 tie-break 规则。
- 闫保捷实现编译期或启动期 feature flag，保证可以一键回到默认调度器。
- 将“选择下一个进程”和“更新进程队列元数据”分成可测试的小块，避免把策略逻辑散落到 sleep/wakeup。
- 通过标准：默认模式与 MLFQ 模式都能启动；策略开关不会改变 syscall ABI。

### M4：时钟抢占与状态迁移

- B 在时钟中断路径实现时间片消耗、降级和周期性提升，明确用户态/内核态计时边界。
- 闫保捷审查 `yield`、`sleep`、`wakeup`、`exit`、`wait` 的队列状态迁移，重点检查锁和重复入队。
- A 扩展快照字段（当前队列、剩余时间片、抢占次数）并保持版本兼容或明确破坏性变更。
- 通过标准：CPU 密集进程会被抢占；IO 密集进程被唤醒后不会永久排队；无可运行进程时不忙等。

### M5：回归、性能和多核验证

- C/D 固定三类负载：CPU 密集、频繁 sleep/wakeup、混合交互负载；每组至少重复 5 次。
- 比较默认策略和 MLFQ 的吞吐、响应延迟近似值、等待时间、抢占次数；同时记录 QEMU 参数和宿主机信息。
- 闫保捷运行完整 `usertests`、已有 `test-xv6.py` 和新测试，处理只在多核出现的锁/计数竞态。
- 通过标准：没有新增 panic、死锁、丢失唤醒或僵尸回收回归；报告同时展示原始数据和汇总方法。

### M6：收敛与发布

- 冻结 syscall 和配置命名，删除调试打印，补充错误路径和注释。
- D 整理从零开始的构建与实验命令；C 更新用户使用示例；A/B 完成接口和策略设计文档。
- 闫保捷做最终 rebase、标记版本并发布报告，保留“已知限制”和后续选题（多级反馈参数自适应、调度器插件化等）。

## 6. 风险与决策闸门

- **计时位置不一致**：先定义“运行时间”和“等待时间”的边界，再写代码；否则不同成员的计数不可比较。
- **锁顺序变化**：任何新增锁或跨进程扫描都必须在 PR 中写出锁顺序；发生死锁时优先缩小临界区，不直接关闭锁。
- **多核非确定性**：性能结论只能报告分布或重复实验结果，不能用一次 QEMU 输出下结论。
- **ABI 过早冻结**：M2 先以最小只读接口为主，M3 评审字段后再让用户工具依赖它。
- **范围膨胀**：文件系统、网络、实时调度和图形界面不属于本阶段；新增想法进入 issue，不直接插入当前里程碑。
